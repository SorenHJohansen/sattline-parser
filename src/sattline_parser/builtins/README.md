# Builtin language data

This package holds the parser's builtin language facts: function signatures and
record field specifications. It contains no validation policy and no
consumer-specific data.

## Function signatures

`catalogue.json` is generated by `scripts/gen_builtin_catalogue.py` from
`scripts/builtin_catalogue_source.json`. Never edit the generated file by hand.

### Sources

The signatures are transcribed from the public SattLine builtin documentation:

- **SattLine Language User manual**, System Version 3.1, chapter 2,
  "System procedures and functions", sections 2.6-2.35. This is the primary
  source for the documented total.
- **SattLine I/O and Communication User manual**, System Version 3.1, for
  `DefineStaticRouting` and `RemoveStaticRouting`.
- **SattLine General and Graphics User manual**, System Version 3.1, for
  `SaveVariableCoded` and `VSSGetLastError`.
- **SattLine 3.1 Additional features**, System Version 3.1-2, for
  `GetUserIdleTime`.

### Coverage

The generated header records the numbers. At the time of writing:

- 171 documented functions are carried with a full signature.
- 2 documented functions are carried without a typed parameter list
  (`GetPrivilegeFlag`, `ResetPrivilegeFlag`); they still carry their arity.
- 9 names are carried but are not located in any public manual in the
  reference set. They are listed under `meta.not_located` in the catalogue and
  are kept only so arity checks keep working for them.
- No documented name is omitted.

`EqualString` is documented with that spelling; the catalogue carries
`equalstrings` as the canonical key and `EqualString` as an alias.

Parameters documented as optional carry `"optional": true`. Optional
parameters are trailing-only; the generator rejects a required parameter after
an optional one. The validator uses the leading required count as a call's
minimum arity.

### Regeneration

```bash
python scripts/gen_builtin_catalogue.py          # rewrite catalogue.json
python scripts/gen_builtin_catalogue.py --check  # verify it is current
```

A test runs the `--check` path, so a stale catalogue fails the suite.

## Record field specifications

`records.py` holds `BUILTIN_RECORD_SPECS`: the ordered field list for each
builtin record datatype, plus the opaque and fieldless name sets and
`BUILTIN_DECLARED_DATATYPE_NAMES`. The field tables are transcribed from the
builtin datatype reference in the SattLine General and Graphics User manual and
the SattLine I/O and Communication User manual, both System Version 3.1.
Consumers resolve a field path against these specs; the package does not decide
whether a field access is valid.
